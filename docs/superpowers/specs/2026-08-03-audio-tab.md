# Audio Tab — Functional Audio Panel

## Problem

The editor's **Audio** tab in the left asset library is a placeholder. `assetLibraryPanel.tsx:435` renders `<EmptyTab label="Audio browser coming soon" />` — the user cannot browse, play, import, or generate audio from this panel. Meanwhile the backend and the rest of the frontend already fully support audio:

- Backend: audio asset import, presigned playback URLs (`/api/assets/{id}/url`), `mixAudioLayer`/`mixAudioTracks` in the renderer, `transcribe`, AI generation (`voiceover`, `music` tier-1 jobs).
- Frontend: `useAssetStore` holds all assets; `addAssetLayer` already routes `kind === "audio"` to the `audio` track; the Media tab already lists audio assets alongside video/image; the AI Assist tab already generates voiceover + music via `Tier1Modal`; the preview and timeline already treat audio layers as first-class.

The Audio tab should become a real, audio-specific surface: browse audio assets with inline preview, import audio files, add them to the timeline, and kick off AI generation — with the asset list auto-refreshing when a generation job completes.

## Goal

Make the Audio tab actually work: an audio-only browser (list + search + import + inline play/pause + click/drag to add to timeline) combined with AI generation, reusing existing infrastructure end-to-end.

**Out of scope:** backend changes, new API endpoints, changes to the Media tab's behavior, audio mixing/effects in the renderer, playback inside the timeline/preview.

## Requirements (from design session)

1. **Browse** — show all `kind === "audio"` assets (uploads + AI-generated) in a grid matching the Media tab's look.
2. **Search** — a local search field filtering the audio list by name (isolated from the Media tab's store-level query).
3. **Import** — an `audio/*`-only import button (file picker), same import flow as Media tab (`importAsset` + `addImportedAsset` + toasts).
4. **Inline play/pause** — per-row play button streaming the asset's presigned URL through a single shared `<audio>` element; only one plays at a time.
5. **Add to timeline** — click / Enter / Space (and drag-and-drop) adds the asset via `addAssetLayer(asset, 0)` → lands on the `audio` track.
6. **AI generation** — a "Generate with AI" button reusing the existing `Tier1Modal` (voiceover/music/image/video modes + progress drawer), no new backend work.
7. **Auto-refresh** — when a voiceover/music job reaches `completed`, call `loadAssets(projectId)` so the new audio appears automatically.
8. **Empty & error states** — `ErrorBanner` with retry; loading spinner; "No audio yet" empty state.

## Decisions

- **Approach: dedicated `AudioTab` component** (not a generalized shared grid). Keeps the change additive and low-risk: replace one placeholder line with one `<AudioTab />` mount, reusing the exact drag payload, store, modal, and progress drawer that already exist. The Media tab's inline grid stays untouched.
- **Playback: one shared `<audio>` element** with `playingId` state. No per-row `<audio>` elements, no audio waveform/visualizer (scope).
- **Generation UI: reuse `Tier1Modal` as-is.** Mounting it a second time is safe — `AgenticProgressDrawer` open state is local to the modal.
- **Auto-refresh via `useAiUiStore.activeJob` + `subscribeToJob`.** When an audio-kind job (`voiceover`/`music`) completes, `loadAssets(projectId)` is called. Refresh only on `completed`, not `failed`.
- **Click adds at time 0** (`addAssetLayer(asset, 0)`), identical to the Media tab today. Drag-drop uses the existing timeline drop handler which resolves `audio` → audio track.
- **Commit hygiene:** `assetLibraryPanel.tsx` carries unrelated uncommitted edits. The mount + import will be committed with a **hunk-split staged patch** (same technique as the TextTab mount) so the unrelated changes are not included.

## Implementation Sketch

### `audioTab.tsx` (new)

- `"use client"`; imports: React hooks, lucide icons (`Music`, `Plus`, `Search`, `Loader2`, `Play`, `Pause`, `Tag`, `Trash2`, `X`, `Upload`), `Input`, `ErrorBanner`, `Button`, `importAsset` + `getAssetUrl` from `@/lib/api/assets`, `subscribeToJob` from `@/lib/api/jobs`, toast helpers, `cn`, `useAssetStore`, `useTimelineStore`, `useAiUiStore`, `Asset`/`AssetKind` types, `Tier1Modal`. (No `useEditorStore` — click-to-add uses `addAssetLayer(asset, 0)`, no playhead.)
- Note: `formatDuration`, `THUMB_BG`, `THUMB_ICON`, `THUMB_ICON_COLOR` are **file-local** in `assetLibraryPanel.tsx` (not exported). Define local copies in `audioTab.tsx` with the same values — this mirrors the existing duplication between `assetLibraryPanel.tsx` and `assets/page.tsx`.
- Local state:
  - `searchQuery: string` — local (isolated from Media tab store query).
  - `playingId: string | null` — which row's audio is currently playing.
  - `tagEditingId`, `tagDraft` — tag edit state (same as Media tab).
  - `importing: boolean`, `audioInputRef` — import flow.
  - `tier1Open: boolean` — "Generate with AI" modal.
- `audioRef = useRef<HTMLAudioElement | null>(null)` — single shared audio element.
- Derived: `audioAssets = assets.filter((a) => a.kind === "audio")`; `filtered` applies `searchQuery` name match.
- Load on mount: `useEffect(() => { if (projectId) void loadAssets(projectId); }, [projectId, loadAssets])`.
- Tag add/remove + delete handlers — port the Media tab's `addTag`, `removeTag`, `handleDelete` verbatim.
- `addToTimeline(asset)` → `useTimelineStore.getState().addAssetLayer(asset, 0)`.
- `togglePlay(asset)`:
  - If `playingId === asset.id` → pause + reset `playingId`.
  - Else → `getAssetUrl(asset.id)` → `audioRef.current.src = url` → `play()` → `setPlayingId(asset.id)`; handle `onEnded`/`onPause` → `setPlayingId(null)`.
  - Prevents calling play when the previous source is still loading (track a loading guard if needed).
- `importFiles(files)` — filter `file.type.startsWith("audio/")`, call `importAsset(projectId, "audio", file)`, `addImportedAsset(...)` with `source: "upload"`, toast success/error per file (port Media tab's loop, audio-only).
- Auto-refresh effect:
  ```
  const activeJob = useAiUiStore((s) => s.activeJob);
  useEffect(() => {
    if (!activeJob || (activeJob.kind !== "voiceover" && activeJob.kind !== "music")) return;
    let disposed = false;
    const unsubscribe = subscribeToJob(activeJob.jobId, (msg) => {
      if (disposed) return;
      if (msg.status === "completed" && projectId) void loadAssets(projectId);
    });
    return () => { disposed = true; unsubscribe(); };
  }, [activeJob?.jobId, projectId, loadAssets]);
  ```
- Render:
  - `<audio ref={audioRef} className="hidden" />` (single shared element).
  - Search input (local query).
  - "Import audio" dashed button + hidden `input[type=file] accept="audio/*"`.
  - "Generate with AI" `Button` → `setTier1Open(true)`; `<Tier1Modal open={tier1Open} onOpenChange={setTier1Open} />`.
  - `ErrorBanner` on error with retry.
  - Loading spinner / grid of audio cards / empty state.
  - Card: thumbnail block (Music icon, `#14532D`, `#22C55E`), play/pause button overlay or in meta row, name, `formatDuration`, source badge (optional), tags row, tag-edit input, delete button.
  - `draggable`, `onDragStart` (same JSON payload + `effectAllowed="copy"` + `onDragEnd` dispatching `lumora:drag-end`), `onClick`/`onKeyDown` (Enter/Space) → `addToTimeline`.

## Risks & Mitigations

- **Audio autoplay blocked by browsers** — playback is user-initiated (button click) so it is allowed; no autoplay on mount.
- **Presigned URL expiry** — fetch `getAssetUrl` fresh at play time (never cached), same as the preview panel.
- **`subscribeToJob` WebSocket down (backend Redis/WS offline)** — drawer already falls back to polling; AudioTab may miss a refresh in that case; the Media-tab `loadAssets` on mount + manual retry cover it. Acceptable for this scope.
- **Two `Tier1Modal` instances (Ai Assist + Audio tab)** — safe: drawer open state is local; both read `useAiUiStore.activeJob`.
- **Regression on the dirty `assetLibraryPanel.tsx`** — hunk-split staged patch only touches the import + the one placeholder line.
